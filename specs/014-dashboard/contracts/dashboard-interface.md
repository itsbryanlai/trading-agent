# Contract: the dashboard service's interface

How the dashboard is started, configured and checked, and what it logs. Routes: [routes.md](routes.md). Research: D2, D5, D16–D18.

## Command

```text
python -m trading_agent.dashboard                  # serve on 0.0.0.0:$PORT
python -m trading_agent.dashboard --check          # one line per check; writes nothing
python -m trading_agent.dashboard --hash-password  # prompt twice, print the hash
```

| Exit | Meaning |
|---|---|
| 0 | served until SIGTERM; every check `ok`; a hash printed |
| 1 | at least one check failed; serving stopped on an unexpected error |
| 2 | refused: a required variable missing, `config/dashboard.yaml` invalid, an unknown flag, a password shorter than 16 characters or the two entries differ |

`--hash-password` needs no variable and no database. `--check` needs all four variables and both databases reachable.

## Environment (the service's only variables)

| Variable | Holds | Read by |
|---|---|---|
| `DASHBOARD_DATABASE_URL` | `ta_dashboard_login`'s connection string | `store`, the health check, `--check` |
| `DASHBOARD_CONTROL_DATABASE_URL` | `ta_dashboard_control_login`'s connection string | `control` only (guard test) |
| `DASHBOARD_PASSWORD_HASH` | `scrypt$32768$8$1$<salt>$<hash>` from `--hash-password` | `auth`, `--check` |
| `DASHBOARD_SESSION_SECRET` | at least 32 random bytes, e.g. `openssl rand -base64 48` | `auth`, `--check` |
| `PORT` | set by Railway | `__main__` |

No broker, model, market-data or Telegram variable. A missing one of the four refuses start (exit 2) with the variable's name, never a value. All four are listed in `.env.example` with empty values.

## Configuration: `config/dashboard.yaml`

Every key required, unknown keys rejected, bad file → exit 2.

| Key | Type, bounds | Shipped |
|---|---|---|
| `owner_time_zone` | IANA name | `Asia/Singapore` |
| `session_hours` | int, 1–24 | 12 |
| `page_size` | int, 10–200 | 50 |
| `max_sessions` | int, 1–100 | 20 |
| `sign_in_delay.first_seconds` | int, 1–10 | 1 |
| `sign_in_delay.cap_seconds` | int, first–300 | 30 |
| `sign_in_delay.tracked_addresses` | int, 10–100000 | 1000 |
| `database.statement_timeout_seconds` | int, 1–60 | 10 |

The deployed `config/schedule.yaml` is read for `portfolio_manager.run_while_paused` only (research D14).

## `--check` output

```text
database_read: ok
database_control: ok
password_hash: ok
session_secret: ok
schedule: ok
config: ok
```

A failing line reads `<name>: FAILED <code>`; codes are `unreachable`, `wrong_role:<role>`, `extra_role:<role>`, `malformed`, `too_short`, `unreadable`, or an exception type. No value, connection string or database message is ever printed.

## Logs

One line per event on stdout, prefixed `dashboard`:

| Event | Fields |
|---|---|
| `started` | `port`, `config_version` (the file's hash, 8 hex) |
| `stopped` | — |
| `sign_in ok` | — |
| `sign_in failed` | `site_wait`, `address_wait` (seconds now in force) |
| `sign_in too_soon` | `wait` |
| `sign_out` | — |
| `toggle paused` / `toggle resumed` | `at` (UTC ISO time) |
| `toggle refused` | `reason`: `run_while_paused`, `unreadable`, `stale`, `csrf`, `no_session` |
| `toggle failed` | `type` (exception type) |
| `error` | `type`, `route` (the route's template, not the URL) |

Never logged: a password or hash, a cookie, session or CSRF value, a connection string, a client address, a query string, stored model or broker text, a database error message.

## Railway service (`.railway/railway.ts`)

```ts
const dashboard = service("dashboard", {
  source: github("itsbryanlai/trading-agent", { branch: "release/prod" }),
  build: { builder: "RAILPACK", buildCommand: "/app/.venv/bin/pip install -e ." },
  start: "python -m trading_agent.dashboard",
  healthcheckPath: "/healthz",
  replicas: 1,
  env: {
    DASHBOARD_DATABASE_URL: preserve(),
    DASHBOARD_CONTROL_DATABASE_URL: preserve(),
    DASHBOARD_PASSWORD_HASH: preserve(),
    DASHBOARD_SESSION_SECRET: preserve(),
  },
});
```

The guard test (`tests/unit/deploy/test_deployed_shape.py`) gains: `dashboard` holds exactly these four names; `healthcheckPath`, `domains`, `networking`, `tcp` and `tcpProxies` appear on `dashboard` only; `DASHBOARD_*` names appear on no other service; one replica. The public domain is generated by the owner after apply (research, "Things flagged" 2).
